What this experiment measures.

Streamstar implements the Group 26 proposal, Drift-Adaptive Federated Sketching for Privacy-Preserving Streaming Frequency Analytics. It is a research pipeline with a Go window processor, simulated client groups, sketch protocols, accounted privacy, replay/Kafka ingestion, and a live evaluation dashboard.

This UI includes exact truth, errors, clipping counts, and multiple protocol outputs. These research diagnostics are not differentially private. Per-method budgets characterize the corresponding private mechanism in isolation, not the entire dashboard.

Three base sketch constructions

The implementation follows Algorithms 1 and 2 of Wu et al. (2023). Bucket assignments and random signs have deliberately different lifetimes.

All estimates are divided by the same public window capacity. The row sum implements the paper's average across cohorts with normalization applied at the end. The paper studies cohorts of distinct users; this extension can reuse client groups over overlapping windows and therefore applies conservative trajectory-level composition.

Contribution bounds and Gaussian accounting

There are n public client-group slots, M cohorts in the active window, and at most C events per group per cohort. The latest C events are retained. Event frequency is count divided by nCM, not the observed private event total. Empty slots remain in the denominator.

Neighboring relation: replace one group's complete trajectory
Hybrid/Fresh L2 sensitivity ≤ 2C √(M × rows)
Shared L2 sensitivity       ≤ 2CM √rows
Gaussian standard deviation = multiplier × sensitivity
ρ per Gaussian query        = 1 / (2 × multiplier²)
ε(δ)                        = ρ + 2√(ρ log(1/δ)) + pure ε

The bound applies to the joint vector of all cohort sketch blocks. Overlapping windows compose sequentially with no assumed subsampling amplification. Gaussian bucket sensitivity is independent of width for fixed rows and clipping. This implementation does not manufacture a width-dependent noise scale to obtain a U-shaped curve.

Adaptive width and private release gate

Each adaptive round first spends budget on a Gaussian-noised probe. The probe's top estimates are fitted to βr−α by value-space least squares. The oracle-inspired head/tail heuristic chooses a power-of-two width. If there is not enough signal above the estimated noise floor, the current width is retained.

A Page-Hinkley detector observes a noise-adjusted distance between the private probe and the last published private probe. A change in the leading IDs is visible even when concentration remains constant. Resizing and release decisions are postprocessing of the paid probe. A public maximum-staleness setting also triggers releases. Reused estimates are evaluated against the current truth so their stale error is included.

Stable rounds spend no additional release budget; probes still cost privacy. A finite cap stops further queries. There is no claim that finite privacy spend can sustain accurate publication on an arbitrary infinite changing stream.

Local DP and the PrivSketch reproduction

Strict sampled Count-Min LDP

Each client group's bounded window is padded with a public null item. A uniformly sampled sketch coordinate is stochastically encoded and privatized with binary randomized response. The server decodes each report, aggregates it, and applies count-mean collision correction. The complete input vector is protected by pure ε-LDP per report. Sequential composition protects a repeatedly participating group.

p = exp(ε) / (1 + exp(ε))
Pr(report = 1 | bounded counter x) = (1-p) + (2p-1)x
Debiased counter = (report - (1-p)) / (2p-1)
Count-mean correction = (estimated bucket mass - 1/W)/(1 - 1/W)

Paper PrivSketch

The reproduction follows Li et al. (2023): boolean Count-Min encoding, a randomly tie-broken ordering matrix, a sampled randomized-response counter, and decode-first aggregation using the minimum ordered query counter. Its estimate is client presence, not event frequency.

The data-dependent ordering matrix excludes possible inputs. The source paper provides a conditional indistinguishable-input-set argument; that does not establish ordinary full-domain LDP for the joint transcript. Its displayed epsilon accounts for randomized response only and is marked conditional. Keep this method separate from a standard-LDP comparison.

Secure summation simulation

Client vectors are split into two uniformly random additive shares over the 64-bit ring. Two simulated noncolluding helpers aggregate their shares; only the sum of those aggregate shares is reconstructed. The helpers and raw replay stream run in one process, so this is an executable simulation, not a deployment security boundary. There is no dropout handling, authentication protocol, or malicious-client defense.

Metrics and reproducibility

ℓ∞ and MSE use signed, unclipped estimates over the full public domain. NCR follows Li et al.: a true item at rank i earns quality k+1−i, and an item outside the true top-k earns zero. The estimated set’s total quality is divided by k(k+1)/2. The paper’s VAR metric (top_k_variance) is count-scale mean squared error on the intersection of estimated and true top-k. If the intersection is empty, VAR is undefined and recorded as zero with top_k_intersection=0. Normalized error variance on all true top-k is separately recorded as top_k_error_variance. Throughput is events divided by total processing time across the seven methods; it excludes the source tick wait. Memory is sketch payload size, not total Go heap use. Communication counts two 64-bit helper shares, including probes; transport framing, setup, and cryptographic overhead are excluded.

Source events are seeded. Privacy noise uses crypto entropy unless deterministic research mode is explicitly enabled. The CLI exports per-round CSV, run configurations, and summaries. Use repeated seeds, fixed-width sweeps, and matched cumulative privacy levels to test the hypotheses. Recovery is the first post-drift round whose ℓ∞ meets the configured target, before the next drift; unrecovered cases are null.

Current boundaries

  • Exact diagnostics, labels learned from replay, and the dashboard are research outputs.
  • Privacy ledgers are in-memory and reset with a process or experiment restart. Production needs durable accounting, isolated helpers, a private-only API, and secure client ingestion.
  • The width policy and gate are experimental heuristics. The project does not assert the proposal's hypotheses are proven.
  • The source pipeline uses Go count-based sliding cohorts instead of Flink, and the built-in dashboard instead of InfluxDB/Grafana. Kafka remains supported.
  • Public integer-domain hashes use reproducible SplitMix64 families, not a proof of fully independent random hashes.
